Swiss careers policy scanner

A small local PoC for screening company websites before collecting job data. No API key, model account or Python packages required.

1. Try the included report

Unzip the package and open HOWTO.html. The offline demo contains five clearly labelled synthetic cases: Good, a scraping restriction, an AI-bot exclusion, missing terms, and no careers page. Use the report buttons to filter results and the links at the bottom to open the CSV lists or full evidence.

The separate real scan uses Swisscom and Digitec Galaxus. Its timestamps and evidence describe the run included in the package. Website content and policies can change.

2. Run the scanner

You need Python 3.11 or newer. This package was tested with Python 3.14.5 on macOS. In Terminal, enter the extracted folder:

cd UZH-Demo-Library/Job-Scraper-Tooling
python3 --version
python3 demo.py
open demo-output/report.html

If Python is missing, install a supported Python 3 version from python.org. There is no pip install step.

3. Supply company websites

Edit sites.csv with a text editor. Use one company per row, up to 20 per run. Start with the corporate homepage rather than a consumer shop landing page. The scope is the Swiss companies you supply; the scanner does not search all Swiss websites or verify company domicile.

company,url,jobs_url,terms_url
My company,https://www.example.ch/,,

The last two columns are optional hints. If the site hides links behind JavaScript, paste the exact careers and terms URLs there. Keep the column headers. Quotes are required around a field containing a comma. The example domain is only illustrative.

python3 scanner.py --input sites.csv --out output
open output/report.html

Save each run separately when comparing changes, for example --out scans/2026-11-06. Reusing an output folder replaces that report and its CSV/JSON files. The scanner prints results as it progresses and writes the report after every company.

4. Understand the decisions

  • Good: a company-hosted careers page and at least one terms/legal document were confirmed; no matching restriction, ambiguity or fetch issue was detected.
  • Blacklist: a restriction matched in checked terms, robots blocked the homepage/careers path, or a checked AI bot was excluded from the careers path. The reason distinguishes these cases.
  • Review: missing terms, inaccessible or unsupported documents, external careers platforms, ambiguous policy wording, crawl limits, or network failures.
  • No jobs found: no careers link was discovered on the input page. This does not prove that the company has no jobs.

Good means “no restriction detected by this heuristic”, not permission or legal clearance. Before a real collection job, review the evidence and the site's applicable terms. A blacklist entry is this tool's conservative decision, not a legal conclusion about the company.

5. What it checks

  1. Fetch /robots.txt before the homepage, careers pages or terms. Redirect targets get their own robots check.
  2. Discover up to three careers links and five terms/legal links, including legal links on careers pages.
  3. Look for English, German, French and Italian expressions around scraping, automated access, AI and data mining in those legal documents. Store the matched passage and source URL.
  4. Evaluate robots rules for SwissJobsPolicyCheck, the scanner's actual user agent. Also report careers-path exclusions for GPTBot, ClaudeBot, Google-Extended and CCBot, without using those identities for requests.
  5. Write the four CSV lists, a filterable HTML report and results.json with timestamps, response hashes, HTTP statuses, robots text and excerpts.

AI-training exclusions do not necessarily forbid ordinary job indexing. This PoC deliberately excludes those sites pending review. A missing robots file with HTTP 404/410 permits the policy check to continue, but does not grant permission. A 401/403 robots response is conservatively blacklisted; other failed robots checks go to Review.

6. Limits of this PoC

  • It screens supplied URLs; it does not download individual job listings, applicant data or crawl the whole web.
  • It uses bounded HTML discovery and keyword rules, not AI interpretation of contractual meaning. False positives and missed clauses are possible. Negation, cross-references, indirect restrictions and unsupported languages need human review.
  • External ATS domains are not confirmed as company-owned. Same-host/subdomain checks are a hostname heuristic, not proof of ownership. Discovered external links are flagged; redirects are followed only with public-host validation and robots checks, then external ownership is flagged.
  • No JavaScript rendering, login, PDF policy extraction, CAPTCHA solving, proxy rotation or bypassing of access controls.
  • Each company is limited to 30 requests, 1 MB per response and a 12-second socket timeout. Requests are at least one second apart per origin. Supported crawl delays up to ten seconds are honoured; larger delays and request-rate directives require review. There is no whole-run time deadline.
  • The local CLI rejects private/reserved destinations and nonstandard ports. It is not a hardened internet-facing fetch service and does not pin DNS resolutions against rebinding. Do not expose it as a public API.
  • Robots matching covers groups, Allow/Disallow, longest match, wildcards, end anchors and percent-encoded paths. It is a small tested implementation, not a claim of complete RFC conformance.

7. Verify or extend

python3 -m unittest -v

The tests cover classification, multilingual restriction examples, irrelevant AI news, missing terms, external ATS links, robots precedence and redirect checks, private addresses, escaped report content and exports. Add a fixture for a new policy wording before changing the matcher. For a larger next version, use manual acceptance records and a semantic classifier for ambiguous terms; keep the original evidence and conservative fallback.

Technical reference: RFC 9309, Robots Exclusion Protocol. Its introduction explicitly separates robots rules from access authorization.
